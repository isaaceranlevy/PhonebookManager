# Nimbus Phonebook Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Execute inline and obtain one independent review at the end.

**Goal:** Deliver a single executable Hebrew phonebook manager for Windows and Yealink.
**Architecture:** Immutable snapshots pair validated JSON with generated XML; atomic disk replacement precedes publication. Separate loopback administration and LAN read-only listeners.
**Tech Stack:** Go; x/sys and x/text only; embedded vanilla HTML/CSS/JS.
**Spec:** ../specs/2026-10-29-nimbus-design.md (user supplied and authorized).

## Global Constraints
- Admin 127.0.0.1:8765; phones 0.0.0.0:8088; no CORS or CDN.
- 1000 contacts, 64-character names, 32-character numbers, JSON 1 MiB, CSV 2 MiB; configurable.
- Two Yealink formats, 10 rolling backups, revision conflict detection; no XML disk files.
- Windows SCM, recovery, subnet-scoped firewall and SYSTEM/Administrators ACL.
- Existing cloud task is isolated; use its checkout. Do not publish environment or push.

## Review Focus
- Corrupt primary and corrupt latest backup: recover most recent valid snapshot without destroying evidence.
- Empty imports, duplicates, malformed JSON and CSV: reject dangerous ambiguity, preview without mutation.
- Disk failure and concurrent reads: durable old state or complete new state only.
- Remote Host/Origin and phone endpoint isolation: fail closed.
- Service installation rollback and shutdown: report failures and release listeners.
