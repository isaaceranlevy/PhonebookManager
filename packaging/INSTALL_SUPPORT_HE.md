# Nimbus — התקנה ראשונית לתמיכה

המטרה: הלקוח מקבל קובץ התקנה אחד, מתקין ופותח קיצור דרך. התמיכה מבצעת פעם אחת את חיבור הטלפונים.

## לפני ששולחים את הקובץ

1. בחרו מחשב Windows 64 ביט שיישאר דלוק ומחובר לרשת. על Windows 10 נדרשת מערכת נתמכת/מעודכנת לפי מדיניות הארגון; מומלץ Windows 11.
2. קבעו למחשב כתובת קבועה, בדרך כלל באמצעות הזמנת DHCP בנתב. המתקין אינו משנה את כתובת המחשב.
3. בדקו מהי רשת הטלפונים המורשית, למשל `192.168.1.0/24`, ושהלקוח מאשר הגשת הספר ב־HTTP ברשת זו.
4. ודאו שהרשת מוגדרת ב־Windows כפרטית או כרשת ארגונית מאושרת. אין לשנות פרופיל של רשת ציבורית בלי אישור.
5. שלחו רק את **NimbusPhonebook-Setup-1.1.0.exe** ואת מדריך הלקוח. אין צורך ב־Git, ב־Go או בקובצי המקור אצל הלקוח.

המתקין אינו חתום דיגיטלית בשלב זה. אם מדיניות הלקוח חוסמת קובץ לא חתום, יש להסדיר חתימת קוד/אישור ארגוני לפני הפריסה; אין להנחות לקוח לבטל מנגנוני הגנה.

## ההתקנה — מה הלקוח עושה

1. מפעיל את קובץ ההתקנה ומאשר את בקשת הרשאות המנהל של Windows. אם אין הרשאות, התמיכה/מנהל המחשוב מבצעים את ההתקנה.
2. במסך **חיבור לרשת הטלפונים**, מאשר את הרשת שסוכמה עם התמיכה. רשת יחידה מזוהה מוצעת אוטומטית; זיהוי אינו אישור גישה. כשמופיעות כמה רשתות, התמיכה בוחרת את הנכונה.
3. ממשיך להתקנה וממתין להודעת הסיום.
4. פותח **Nimbus - ספר הטלפונים** משולחן העבודה.

אם פועל עדיין `phonebook.exe run` מהניסיון הידני, יש לסגור אותו לפני התקנת השירות, כדי לפנות את הפורטים.

## מה המתקין מבצע

- מתקין את התוכנה ואת ההדרכה לתיקייה קבועה תחת Program Files.
- יוצר שירות Windows שעולה אוטומטית, כולל הפעלה מחדש במקרה של כשל.
- מגביל את חומת האש לתת־הרשת שנבחרה, בפורט הטלפונים בלבד, בפרופילים פרטיים/ארגוניים.
- שומר נתונים וגיבויים ב־`%ProgramData%\NimbusPhonebook` עם הרשאות SYSTEM ומנהלים.
- בודק שהשירות וממשק הניהול זמינים לפני הצגת סיום מוצלח.
- יוצר קיצור דרך לניהול ומתקין מדריך שימוש מקומי. שימוש יומיומי בדפדפן אינו דורש הרשאות מנהל.

## חיבור הטלפונים — באחריות התמיכה

1. פתחו את הספר דרך הקיצור, הוסיפו איש קשר בדיקה ושמרו.
2. פתחו **חיבור הטלפונים** והעתיקו את כתובת ה־XML של הרשת המתאימה.
3. ממחשב נוסף ברשת המורשית בדקו שהכתובת מציגה XML. דוגמה: `http://192.168.1.100:8088/phonebook.xml`.
4. בממשק Yealink פתחו **Directory → Remote Phone Book**. הדביקו את הכתובת בשדה **Remote URL**, תנו שם לספר ושמרו.
5. פתחו את הספר בטלפון ובדקו שהאיש שנשמר מופיע ושהחיוג תקין.

**אין להזין בטלפון `127.0.0.1` או את פורט הניהול `8765`.** כתובת הטלפונים משתמשת ב־IP של המחשב, בפורט `8088` ובנתיב `/phonebook.xml`. אם הותאמו פורטים בהתקנה קודמת, השתמשו בכתובת שהאפליקציה מציגה.

את תזמון הרענון מגדירים בטלפון. בדקו בפועל כמה זמן עובר משמירה ועד עדכון; אין צורך לשנות פורמט XML שכבר עובד.

## בדיקת מסירה קצרה

1. קיצור הדרך פותח את הממשק ללא חלון פקודות וללא בקשת מנהל.
2. איש קשר נשמר, נשאר לאחר רענון ומופיע ב־XML ובטלפון.
3. הפעילו מחדש את המחשב ובדקו שהספר חוזר לפעול אוטומטית. בדיקת זמינות לטלפון צריכה להיעשות גם ללא משתמש מחובר.
4. ודאו שרק הרשת שאושרה מגיעה לספר ושהניהול אינו נגיש ממחשב אחר.
5. מסרו ללקוח את מדריך השימוש והסבירו שהמחשב צריך להישאר פעיל.

## שדרוג והסרה

- **שדרוג:** מריצים את המתקין החדש על אותה התקנה, באותה רשת מורשית. המתקין שומר על הספר, הגיבויים וההגדרות. אין לשנות את רשת הטלפונים כחלק משדרוג שגרתי.
- **הסרה:** דרך הגדרות Windows → יישומים → Nimbus Phonebook → הסר התקנה. הנתונים והגיבויים נשארים ב־ProgramData. המחיקה שלהם, אם נדרשת, היא פעולה נפרדת של התמיכה לאחר גיבוי ואישור.
- אם התקנה קודמת נרשמה עם קובץ הפעלה או תיקיית נתונים אחרת, המתקין יעצור במקום לדרוס אותה. התמיכה צריכה לתכנן את המעבר בנפרד.

## טיפול בשלוש תקלות נפוצות

- **התקנה נעצרת:** בדקו את ההודעה. תהליך קונסול ישן, רשת שונה מההגדרה הקיימת, קובץ הגדרות פגום או התקנה במיקום אחר דורשים טיפול לפני ניסיון נוסף. במצב שחזור שלא הושלם, אל תמחקו `phonebook-previous.exe`.
- **קיצור הדרך לא נפתח:** בדקו ב־Services ששירות **Nimbus Phonebook** פועל. בדקו לוגים בתיקיית `logs` ב־ProgramData.
- **הספר עובד במחשב ולא בטלפונים:** בדקו IP קבוע, Remote URL מלא, רשת מורשית ופרופיל חומת האש. אל תפתחו את ממשק הניהול לרשת.

הספר מכיל מידע עסקי/אישי. אל תשלחו את `book.json`, הגיבויים או הלוגים ללא צורך וערוץ תמיכה מאושר.

## הפצה אוטומטית לתמיכה בלבד

אפשר להריץ מתוך כלי הפצה ארגוני מוגבה: `NimbusPhonebook-Setup-1.1.0.exe /S /SUBNET=192.168.1.0/24`. יש להחליף את הרשת לזו שאושרה. קוד יציאה 0 מציין סיום מוצלח; כל קוד אחר דורש בדיקה. אין צורך לתת פקודה זו ללקוח.
